# 后端交付验收清单

本清单用于 Agent 自检、代码 Review 和发布验收。只对实际执行并取得证据的项目标记通过；不适用项说明理由。

## 意图与边界

- [ ] 已阅读项目 Owner、任务意图和相关历史反例
- [ ] 已依据 DESIGN-REVIEW.md 复查适用设计，明确领域实体、单复数、API 资源边界、数据库约束、页面请求、共享 CLI 与配置；实现后核实相关真实行为
- [ ] 已确认真实消费者、数据 Owner、模块边界和变更范围
- [ ] 没有为单一项目的技术选择制造全局强制要求
- [ ] 新增框架、服务、代理、队列、缓存或抽象有真实问题和收益依据

## 架构与数据

- [ ] 模块依赖方向和持久化写入遵守 Owner 边界
- [ ] 业务身份稳定，唯一性由数据库约束或原子写入保障
- [ ] 身份歧义和冲突被明确暴露，没有静默合并
- [ ] 原始事实、Derived、人工数据、备份、产品对象和临时产物边界清楚
- [ ] 重导、重算和失败重试不会覆盖其他 Owner 的数据
- [ ] 事务围绕真实业务不变量，外部等待不占用长事务
- [ ] migration 可审计、可重放，并考虑新旧代码共存
- [ ] 增长型集合分页稳定、有界，真实读取不是全量后内存切片

## API 与安全

- [ ] API 从消费者任务和领域概念设计，不直接暴露内部实现
- [ ] OpenAPI 等机器可读契约与真实路由、响应一致（适用时）
- [ ] HTTP 方法、状态码、错误响应和缓存语义准确
- [ ] 服务端执行认证、对象级授权和明确字段校验
- [ ] 重复提交、超时和重试不会产生重复业务副作用
- [ ] 请求、上传、响应和外部 URL 有合理的安全边界
- [ ] 密钥不进入仓库、日志、测试产物或公开对象

## 可靠性与发布

- [ ] 外部调用有界超时，重试次数和总等待有界
- [ ] 部分失败有明确状态、恢复或补偿路径
- [ ] 发布责任清晰，目标环境和变更范围可追溯
- [ ] 代码、Schema、数据和对象变更边界明确
- [ ] 重要备份经过真实恢复验证
- [ ] 对象引用、元数据和实际字节一致（适用时）
- [ ] 大对象传输和 Range / seek 经端到端验证（适用时）
- [ ] 发布后执行关键用户路径 Smoke Test；Health 不代替用户路径

## 性能与可观测性

- [ ] 已检查请求扇出、N+1、重复解析、无界查询和资源消耗
- [ ] 性能门槛有用户要求、平台限制、SLO 或实测基线来源
- [ ] 日志、指标和 trace 能关联关键请求与后台任务
- [ ] 日志没有泄露凭据或不必要的敏感数据
- [ ] 告警可行动，未验证的运行路径明确标记

## 三种保障方式

- [ ] 能确定性检查的规则已复用现有工具或进入项目测试/CI
- [ ] Agent 在开发过程中遵循了适用规范，而非只在最后勾选清单
- [ ] 需要业务语义和真实运行证据的内容已做 Review
- [ ] 已确认且可复现的反例已转为回归测试；不能自动化的判断保留在 Agent / Review

## 结果格式

报告用中文分列“已验证 / 已发现问题 / 未验证 / 未运行 / 不适用”。每项已验证必须给出执行命令、证据位置或真实运行结果。不得将文件存在、测试配置存在、CI job 声明存在或 Agent 自述当作检查通过。
