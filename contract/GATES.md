# Gate / Agent / Review 保障矩阵

## 先区分控制方式与检查工具

Draft 中的“现成工具可直接检测”“需要项目专属检测”“Agent Review”“不值得自动化”描述的是检测手段或自动化价值；本文件的 Gate / Agent / Review 描述的是保障发生在哪个阶段。两组概念不能混为一列。

- **Gate**：可确定性判断的约束，由静态分析、成熟工具、自动化测试、数据库 introspection、CI 或部署平台执行。
- **Agent**：开发过程中的判断和行为约束；要求先看 Owner、消费者、真实实现和相关反例。
- **Review**：需要运行证据、业务语义、真实消费者或整体取舍的验收与巡检。

同一规则可同时拥有多个保障层。Gate 不是目标本身；若无法可靠判定，就保留 Agent / Review，不要为了覆盖率制造误报。

## 门禁实施顺序

### 先接入成熟工具

- CI 必需检查与 workflow 权限。
- Secret scanning、依赖漏洞扫描。
- OpenAPI schema lint / compatibility 工具。
- 语言生态已有的 lint、类型检查、测试、格式和构建工具。

这些工具由消费者项目现有生态选择；Contract 不复制实现，也不强制某个供应商。

### 再为真实不变量补项目测试

优先关注：模块依赖方向、持久层唯一性、权限矩阵、分页、幂等与故障恢复、数据 Owner、迁移行为、对象引用闭环、真实请求路径和查询复杂度。

每个项目测试都必须有违规样例和合法样例。已有测试先核实是否覆盖目标行为并进入 CI，不要只因文件名存在就报告已通过。

### 保留 Agent 与 Review 的判断

- 领域概念是否正确、异常数据是否合理、API 是否适合真实消费者。
- 是否真的需要缓存、队列、代理层、微服务或额外抽象。
- 性能数字是否有真实依据。
- 生产用户路径、资源趋势和恢复能力是否达标。

## 明确不做的自动化

不开发仅靠 LLM 给“合规分数”的硬门禁；不通过关键词扫描判断架构优劣；不为每条原则建立独立扫描器；不把没有依据的请求数、毫秒数、并发数或成本数字写进通用 CI；不强制所有项目使用 Golf 的表名前缀、外键颜色或 Trigger 限制。

## 项目检查配置

接入项目在根目录的 backend-contract.json 中声明要运行的检查。配置结构见 schemas/backend-contract.schema.json。命令必须使用参数数组，不使用 shell 字符串；CLI 只执行显式启用的条目。

例如，Python 项目可以配置：

~~~json
{
  "checks": [
    {
      "id": "tests",
      "name": "pytest",
      "command": ["uv", "run", "pytest", "-q", "-m", "not raw_corpus"],
      "cwd": ".",
      "required": true,
      "enabled": true
    },
    {
      "id": "lint",
      "name": "ruff",
      "command": ["uv", "run", "ruff", "check", "src", "tests"],
      "cwd": ".",
      "required": true,
      "enabled": true
    }
  ]
}
~~~

TypeScript / Node 项目可以声明 npm 或 pnpm 的现有脚本；Go、Rust 等项目声明各自真实使用的命令。不要复制示例中的命令，必须先核实项目实际入口。CLI 不会因为发现 package.json、pyproject.toml 或 Makefile 就擅自执行其中的脚本。

- 未配置的检查是 UNVERIFIED，不是 PASS。
- 配置但未执行的检查是 NOT RUN。
- 可选检查可设置 required=false；禁用项仍保留其未运行事实。
- cwd 必须位于消费者项目内部，CLI 会解析符号链接后再次检查边界。
- 命令超时默认 5 分钟，最大 15 分钟；按项目真实运行时间显式调整。
- create 项目默认 strict；adopt 项目默认 incremental。严格模式要求所有必需检查已配置并实际运行。

## 结果语义

所有检查结果必须区分：

- **PASS**：实际执行并取得证据，目标检查通过。
- **FAIL**：实际执行，检查失败。
- **NOT RUN**：已配置但本次未执行。
- **UNVERIFIED**：没有足够检查或证据。
- **NOT APPLICABLE**：经项目上下文确认不适用。
- **CUSTOMIZED**：消费者修改了 Contract 副本，需要人工确认是否仍满足原则。

缺少检查、检查被跳过、证据过期或只读到了配置文件，都不能报告 PASS。
