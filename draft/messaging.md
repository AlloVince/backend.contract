# 消息与异步任务：逐条评估

> 对应来源：../references/messaging.md。主要案例：D-04、D-07～D-08、E-03、E-06、E-11～E-13、G-01～G-03。

| ID | 候选原则 | 第一版结论 | 评估理由与边界 |
| --- | --- | --- | --- |
| MSG-01 | 设计时默认消息可能重复，除非已证明传输保证 | **采用** | 重复投递和消费者崩溃是常见情况。按具体 broker 的真实语义实现，但不能靠“通常只投一次”保证业务正确。 |
| MSG-02 | 消费者幂等围绕业务效果，而非只记录 message ID | **采用** | 同一业务事件可能以不同 ID 重发，单纯去重 ID 不足以保护业务效果。使用唯一业务键或原子状态转换。 |
| MSG-03 | 关键副作用可靠落盘后再 ack | **采用** | 提前确认会在处理失败时丢任务；具体顺序要结合 broker 和数据库事务能力设计。 |
| MSG-04 | 处理未完成前不提前 ack | **采用** | 这是避免任务静默丢失的基本要求。对已经可靠转交给另一个持久系统的情况，需明确新的责任边界。 |
| MSG-05 | poison message 有有限重试和隔离策略 | **修改后采用** | 坏消息不能无限阻塞消费；可以用 DLQ、隔离表或失败队列，取决于平台和规模，不强制所有项目部署独立 DLQ 服务。 |
| MSG-06 | 重试/隔离记录错误、次数、时间和关联 ID | **采用** | 没有这些信息就难以判断是否安全重放。敏感数据不得为了调试被完整复制进日志。 |
| MSG-07 | DLQ 有查看、重放或丢弃流程 | **按需采用** | 只有使用 DLQ 时才适用；若选择别的隔离方式，也必须有明确恢复/删除流程。不能只建一个没人维护的 DLQ。 |
| MSG-08 | 明确消息顺序要求 | **采用** | 全局有序通常成本高，且常见队列只保证有限范围。先说明业务是否真的需要顺序。 |
| MSG-09 | 需要顺序时按稳定业务 key 分区 | **按需采用** | 仅在业务要求同一用户/订单/设备顺序时采用。不要为没有顺序要求的消息额外引入分区复杂度。 |
| MSG-10 | 事件包含消费者需要的稳定业务字段 | **采用** | 消费者不应为处理事件回查生产者内部表结构，否则形成运行时耦合；但也不要把整个数据库对象无差别塞进消息。 |
| MSG-11 | 消息 schema 可版本化，优先向后兼容 | **采用** | 生产者和消费者通常无法同时升级。新增可选字段比重命名/删除字段更安全。 |
| MSG-12 | 生产者和消费者部署不要求绝对同步 | **采用** | 多仓 CI 和独立发布已是现实；契约必须支持部署窗口内的新旧版本共存。 |
| MSG-13 | 有队列时监控积压、延迟、失败和重试 | **修改后采用** | 这些是异步系统的关键健康指标；没有队列就不需要为它建监控。监控应能触发具体处置。 |
| MSG-14 | 重试使用 backoff/jitter | **采用** | 避免下游恢复时集中重试形成风暴。按业务预算设置上限。 |
| MSG-15 | 下游故障时有 backpressure 或容量边界 | **采用** | 无限堆积只会把故障延后成磁盘、费用或恢复问题。限流、暂停消费或有界队列都可以，取决于业务。 |
| MSG-16 | exactly-once 声明限制在真实保证范围内 | **采用** | broker 的事务语义不自动覆盖外部数据库、对象存储或第三方副作用。跨系统仍需要幂等与恢复。 |
| MSG-17 | 重要事件明确 retention/replay，不把队列当永久审计库 | **修改后采用** | 有重放需求的事件需定义保留期；普通短期任务队列不必永久保存。审计和长期数据应放在适当的权威存储。 |
| MSG-18 | 面向用户的长任务可查询状态和最终失败 | **修改后采用** | 用户需要等待、恢复或排错的任务必须有状态入口；不要求简单短任务也建立任务管理平台。 |
| MSG-19 | 长时间/昂贵任务从 checkpoint 恢复 | **修改后采用** | 对可能中断且重做代价高的任务必须考虑 checkpoint；一次性短任务保持简单。D-04 也说明先观测失败原因，再决定是否自动续跑。 |
| MSG-20 | 同步方案足够时不引入消息系统 | **采用** | 事件系统会增加幂等、重放、观测、状态与运维成本。只有独立执行、削峰、异步恢复等收益明确时才引入。 |

## 第一版结论

当前不建议把消息队列作为所有后端的默认底座。先把同步路径做正确、资源有界、故障可观测；只有工作确实需要独立执行、削峰、重试或跨系统解耦时再采用异步系统。
