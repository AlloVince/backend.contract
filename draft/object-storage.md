# 对象存储：逐条评估

> 对应来源：../references/object-storage.md。主要案例：A-02、A-08～A-10、B-01～B-03、C-02、C-06。

| ID | 候选原则 | 第一版结论 | 评估理由与边界 |
| --- | --- | --- | --- |
| OBJ-01 | bucket/prefix 按数据责任、生命周期、权限和公开范围设计 | **采用** | A-09 直接对应。分区依据应是数据责任和生命周期，而不只是“都是文件”或文件后缀。 |
| OBJ-02 | 原始备份、产品对象、临时产物独立治理 | **采用** | 备份不可因普通发布被清空，临时产物应能清理，产品对象有自己的访问策略。三者不能共享一个模糊生命周期。 |
| OBJ-03 | 默认私有，公开对象有明确理由 | **采用** | 降低误暴露风险。公开产品资源可以公开，但不能因为存储桶方便就把备份和原始包公开。 |
| OBJ-04 | 适合时使用短期、范围受限的 presigned URL | **修改后采用** | 对浏览器直传直下有价值；若平台原生绑定能安全处理，也可以不用签名 URL。关键是不能暴露长期凭据，且授权边界清楚。 |
| OBJ-05 | presigned URL 按 bearer token 对待 | **采用** | 持有者可在签名有效期内执行已授权操作，因此不可泄漏到日志、公开页面或不可信消息。 |
| OBJ-06 | presigned 权限限制到操作、对象和期限 | **采用** | 降低链接泄漏的影响范围。有效期应满足实际上传/下载需求，不机械设置到极短导致正常操作失败。 |
| OBJ-07 | 大文件可浏览器直传直下，但保留访问控制 | **采用** | 可避免 Worker/API 无意义中转文件，直接改善 A-02/B-01 的资源路径。需验证权限、文件大小、内容类型与完成状态。 |
| OBJ-08 | 大文件下载不无意义经过 Worker/API 整体转发 | **采用** | 与用户已经明确的前后端分离和静态/大对象路径要求一致。只有授权、转换或审计等真实职责需要时才代理。 |
| OBJ-09 | object key 稳定、可生成，不依赖可变显示名 | **采用** | 文件名和用户显示名可能变化，不能作为唯一业务身份。关联关系应存于权威元数据中。 |
| OBJ-10 | 避免可能被路径层归一化的 . / .. key 片段 | **修改后采用** | 对会映射到 URL、文件系统或代理路由的 key 应避免歧义；对象存储 key 本身是字符串，不应声称所有 S3/R2 key 都会按文件路径解析。 |
| OBJ-11 | 覆盖同 key 前明确策略；重要原始数据考虑 immutable key/versioning | **修改后采用** | 原始备份应避免静默覆盖；可用唯一版本 key、版本控制或其他不可变策略。普通可重建的产品缓存对象未必需要永久不可变。 |
| OBJ-12 | versioning 配合生命周期策略 | **按需采用** | 对误删/覆盖恢复有价值，但会增加存储成本和删除治理复杂度。只有恢复需求值得时启用，并明确版本清理。 |
| OBJ-13 | lifecycle 按数据价值制定 | **采用** | 临时文件、失败上传和中间产物应有清理策略；正式备份的保留期按恢复需求决定。 |
| OBJ-14 | 普通应用发布不能顺带清空备份桶 | **采用** | A-09 是直接反例。发布清理必须只针对其拥有的产物路径，备份清理应是独立且明确的操作。 |
| OBJ-15 | 产品路径不泄漏内部 bucket 和原始包结构 | **采用** | 防止把内部实现暴露成长期 API，并减少用户误用原始包。对公开 URL 只暴露必要的稳定业务路径。 |
| OBJ-16 | 必要时校验上传 size/checksum | **修改后采用** | 大文件、备份和关键数据应验证完整性；对小型可重建资源可依赖平台保证和元数据检查，不强制每次都增加额外读取。 |
| OBJ-17 | 读取、发布、备份、清理权限最小化 | **采用** | 不应让一个发布凭据可以无差别删除所有备份。权限拆分按真实风险和平台支持程度落实。 |
| OBJ-18 | 对象来源/版本/业务归属有权威元数据 | **采用** | 不能只从文件名猜来源或归属。元数据要能追溯到业务实体、导入版本或生成任务。 |
| OBJ-19 | 区分产品隐藏与物理永久删除 | **采用** | 业务不再展示不一定代表应立刻破坏恢复能力。删除策略需符合数据保留和隐私要求。 |
| OBJ-20 | 成本同时考虑请求数、带宽和存储量 | **采用** | C-02 说明请求成本可能远大于存储成本。发布/批处理要减少无必要的 HEAD/LIST/GET/PUT，且不能通过受限 Worker 反复中转。 |

## 第一版结论

对象存储领域优先正式化：**数据生命周期分离、备份与发布隔离、默认私有、直接传输大对象、权威元数据、最小权限与真实请求成本核算。** Versioning、校验和、presigned URL 等具体机制按数据价值与平台能力选择。
