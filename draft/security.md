# API / Web 安全：逐条评估

> 对应来源：../references/security.md。主要案例：A-08～A-09、C-02～C-03、D-01～D-05、G-01～G-03。

| ID | 候选原则 | 第一版结论 | 评估理由与边界 |
| --- | --- | --- | --- |
| SEC-01 | 认证与授权分开处理 | **采用** | 登录只证明身份，不代表可以读取所有对象。权限检查应在服务端执行并与业务数据边界一致。 |
| SEC-02 | 按 ID 访问的用户资源做对象级授权 | **采用** | ID 难猜不是权限控制。每个资源读取/修改都要判断当前主体是否有权访问该对象。 |
| SEC-03 | 角色/功能权限在服务端强制 | **采用** | 前端隐藏按钮只能改善界面，不能阻止直接请求。 |
| SEC-04 | 对输出字段也做权限控制 | **采用** | 把整行数据库对象序列化后再寄希望前端隐藏字段，会造成敏感数据泄漏。输出 schema 应显式列出允许字段。 |
| SEC-05 | 写入字段使用 allowlist / 明确 schema | **采用** | 防止 mass assignment 和用户覆盖内部身份、权限、归属字段。与 A-08 的设备数据/用户数据边界也相关。 |
| SEC-06 | 服务端校验所有外部输入 | **采用** | 前端校验可以改善体验，但请求可绕过前端。类型、范围、关联关系和业务不变量都要在可信边界校验。 |
| SEC-07 | API 对资源消耗设置边界 | **采用** | B-02 与 OWASP API4 对应。限制要覆盖查询条数、上传、批处理、CPU/执行时间和外部调用；数值根据平台和业务定。 |
| SEC-08 | 对敏感/昂贵流程做针对性限流 | **修改后采用** | 登录、导出、昂贵分析等应评估滥用风险；不要不分场景对所有 endpoint 机械套同一限流规则，避免误伤正常用户。 |
| SEC-09 | SSRF 风险点限制目标协议、主机、IP 和重定向 | **按需采用** | 只有服务端会根据用户输入访问 URL、Webhook 或远程资源时才直接适用。没有这类功能就不增加 SSRF 专用机制。 |
| SEC-10 | 密钥不进源码，使用 secret/config 渠道 | **采用** | 所有项目的基本要求。还要核对 CI 日志、错误信息、配置导出和历史提交，不能只检查当前文件。 |
| SEC-11 | 服务账号遵循最小权限 | **采用** | 发布、备份、读取和清理可以有不同权限。权限分离应对应真实风险，不为小型项目无理由创建大量账号。 |
| SEC-12 | 公网入口使用 HTTPS，敏感凭据不放 URL | **采用** | URL 可能进入日志、浏览历史和 Referer。凭据应放合适的 header 或安全机制中。 |
| SEC-13 | 公共错误不泄漏堆栈、SQL、内部主机和秘密 | **采用** | 生产错误响应要稳定且安全；完整诊断放在受控日志并关联 request ID。 |
| SEC-14 | 第三方 API 返回视为不可信输入 | **采用** | 外部服务也可能返回缺字段、错误类型、过大 payload 或不可信内容。必须校验并处理部分失败。 |
| SEC-15 | 维护可用 API/入口清单 | **修改后采用** | 对公网服务、旧版本和管理入口有价值；优先从 OpenAPI、部署配置和路由自动生成/核对，不新增手工重复清单。 |
| SEC-16 | 依赖和运行时有升级及漏洞响应策略 | **采用** | 不要求追每个新版本，但应有受支持版本基线、自动告警和修复流程，避免长期无人维护。 |
| SEC-17 | 敏感管理操作可审计，审计不记录 secret | **修改后采用** | 对权限变更、删除、发布、导出等高影响操作保留审计；不要求每个普通读取都做昂贵审计日志，也要控制个人数据保留。 |
| SEC-18 | 文件上传验证大小、类型、内容和权限 | **采用** | Content-Type 可伪造；需要结合业务允许类型、实际内容、大小与存储访问策略验证。 |
| SEC-19 | CORS 不是认证或授权 | **采用** | CORS 主要约束浏览器读取响应，不能阻止非浏览器客户端直接调用 API。授权必须由服务端完成。 |
| SEC-20 | 安全机制要验证合法路径和恢复路径 | **采用** | D-01/G-01 是直接反例：保护机制把正常 Owner 更新锁死。安全验收不能只证明危险请求被拒绝，还要证明合法用户仍能完成任务。 |

## 第一版结论

安全领域适合进入正式 Contract 的核心是：**对象级授权、输入/输出 schema、资源消耗边界、秘密管理、真实入口验收和合法路径回归。** 不应把每个 OWASP 条目都机械转成 lint；按功能存在与否、威胁模型和实际入口选择检查。
